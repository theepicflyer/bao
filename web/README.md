# Bao web app

SvelteKit (Svelte 5) single-page PWA, built to `build/` and served by the server in `server/`.

```bash
npm install
npm run dev      # Vite on :5173, proxies /api, /auth and /mcp to the backend on :8000
npm run check    # svelte-check, plus tsc for the service worker
npm run build    # writes build/, which the backend serves
```

- The client, data loading and motion come from Warren's web package: `import { get, post, loaded, fly } from 'warren/web'` (its README's "warren/web" section has the parts). Its API client sends `X-Warren: 1` on every request, which the server requires on writes. It is installed from Warren's git repository at the same commit as the server's, with `ignore-scripts=true` in `.npmrc` so npm doesn't build Warren's server half here; it ships TypeScript source, so `vite.config.ts` keeps it out of the dev server's dependency pre-bundling. `npm run dev` proxies to `BAO_BACKEND` when it is set (e.g. `BAO_BACKEND=http://localhost:8010`).
- `src/lib/state.svelte.ts`: Warren's `Session` and `Toasts` set up for Bao (a toast's animal and mood), and the `MediaQuery`s for the wider layouts. The root layout configures the API client (a 401 goes to `/login`) and `loaded()` (a failed load is an error toast) once; signing out calls `forgetData()`.
- A screen that fetches its own data uses `loaded(() => path)`: opened again, it shows its last data at once and refreshes underneath, so going back is instant and lands at the old scroll position. After a write, `changes.changed()` reloads whatever is on screen.
- `src/lib/components/Assistant.svelte` is Bao's message button and chat sheet. It posts to `/api/agent/turns` and reads the server-sent events from the response body. Each opening starts a new thread; when the sheet opens it also loads the day's earlier turns (`GET /api/agent/turns?date=`) and shows them above, with a line between sessions, purely for display. Undo and the thumbs up/down (`PUT /api/agent/turns/{id}/rating`) work on those too. The composer lives only in the sheet; it takes focus on open except on touch screens, where the keyboard would cover the history.
- The UI is built on Burrow, the household design system ([its page](https://claude.ai/artifact/ShL86DzdjvTZDwRHLsd8L4)). Warren hosts it and Bao imports it from there, at the same pin as `warren/web`: `warren/burrow/tokens.css`, `type.css` (the text styles: `card-title`, `body-strong`…) and `burrow.css` (its `bh-*` component classes) at the top of `src/routes/layout.css`, and from `'warren/burrow'` its art (`mascotSVG`, `trailSVG`, `HAB`, `ICONS`…, with the types `Character`, `Mood`, `TraceName`…) and the components shared with Cache: `Mascot`, `Trace`, `Habitat`, `Peek`, `World`, `Breadcrumbs`, `TunnelRow` and `Loader`. Bao keeps no copy; a Burrow update is a re-sync in Warren (its `burrow/README.md`) and a pin bump here. `src/lib/burrow/` holds Bao's own components over Burrow's classes and are ours to change: `Icon` (Burrow's icons plus a few drawn to match), `Field` and `Meter` (with the nutrient symbols), the sunflower `Ring`, `EmptyState`. `TrailPath` is Bao's own: one trail wandering down a screen behind its cards, showing in the gaps between them.
- App-specific classes (`mk-*`) and the Tailwind colour names (`bg-surface`, `text-ink-muted`, `text-accent`…) live in `src/routes/layout.css`. Use Burrow tokens, never raw colours; protein, carbs and fat are `--protein`, `--carbs` and `--fat`, and energy is Bao's own `--energy` (tomato).
- Energy, protein, carbs and fat each have a symbol, `src/lib/components/NutrientIcon.svelte`: a flame, a drumstick, an ear of wheat and a drop, drawn as Burrow stickers in those colours. Use it wherever one of the four is named, never a letter (P, C, F) or a plain colour dot: before the word where there's room (meters, fields via `Field nutrient=`, table headers, tooltips), and on its own before the number where there isn't (`MacroAmounts` for a row's protein, carbs and fat; the flame before a row's calories). Pass `labelled` when no word beside it names the nutrient, so screen readers hear it. Sizes: 16 beside 14px text, 14 beside 12px labels and in `MacroAmounts`.
- Burrow's rules worth keeping when adding a screen: one habitat header and at most one full-size animal per screen (pick the animal by job: Bao for food and the assistant, Gali for history and search, Kayu for settings, editing and errors), one primary button, one trail that ends at the next action (wrap the cards in `TrailPath` with a gap between them, mark the next thing to do with `data-trail-end`, and keep anything inside it opaque or the trail shows through), and no emoji in UI text.
- Every fact has a place (Burrow's principle 8 and its "Where information goes"): never join facts with " · " or leave a line of grey text floating. Short facts are `bh-tag` pills ("No target", "Target 90 g", a meal's kcal beside its title, a food's aliases, `bh-tag--over` for "12 g over", `bh-tag--in` when over is good); dates carry the calendar icon in `bh-when` and use `dayLabel`'s format ("Fri 6 Nov"); a card's explanation goes in `bh-card__sub` under its title (both in `bh-card__heading`), its closing note in `bh-card__foot`; a Tunnel day's total goes in `TunnelRow`'s `aside`; one of a few fixed options (range, meal, nutrition basis) is a `bh-seg` switch, while chips stay for lists that vary (portion units) and for aliases. `MacroAmounts` and the flame before a row's calories are the one place a number stands without its unit: the symbol names it.
- Burrow is phone first and has no wider layouts, so Bao adds two (`src/lib/state.svelte.ts` has a `MediaQuery` for each, for where a screen changes structure; plain `sm:`/`lg:` classes where it only changes size):
  - From 640px (Tailwind `sm`, `columns.current`): unfolded foldables (a Pixel Fold's inner screen is about 790 px wide; its cover screen stays a phone) and tablets. The page column fills the width and screens lay out in columns, while the bottom nav and Bao's message button stay as on a phone, so unfolding keeps them where they were; sheets become centred dialogs. Today puts the sunflower and macros in a sticky left column beside the meals, in equal halves; History is the desktop dashboard with its charts stacked; Foods and Settings use two columns.
  - From 1024px (Tailwind `lg`, `wide.current`): desktop. The bottom nav becomes `SideNav`, a rail with the same links (`src/lib/nav.ts`) and Bao peeking over its top edge; the page column widens to `max-w-6xl` and habitats round all four corners; Bao's message button (`Assistant inline`) moves into Today's left column; History is a 12-column dashboard that ends at the table of days.
  - Half-folded, Chrome reports the fold through the Viewport Segments API. In book posture (the fold top to bottom: `@media (horizontal-viewport-segments: 2)`, the `book:` variant, `book.current`) the two-column screens already split either side of it; the nav, message button, toasts and sheets keep to the left-hand segment (`--fold-right`); History swaps its dashboard for the phone's cards beside the tunnel of days; the food page and sign-in keep to the left. In tabletop (the fold across) sheets move to the top half (`--fold-bottom`, `--sheet-h`) and the rest already sits clear of it. To try it, DevTools' foldable presets have a fold; in a script, the CDP's `Emulation.setDeviceMetricsOverride` takes a `displayFeature` (Playwright's own screenshots reset it, so capture with `Page.captureScreenshot`).
  - Each screen keeps one habitat and one trail at every size. Anything `fixed` positions itself with `--rail-w`, `--dock-h` (the bottom nav, 0 on desktop), `--message-h` (what toasts clear above the nav for Bao's round message button on day screens, 0 on desktop) and `--fold-right` rather than hard-coded offsets. On phones Bao peeks over that round button (`mk-fab`) and ducks behind the nav, so a day screen still has one peek. Charts in a grid cell need `min-w-0` and a `grid-cols-1` wrapper, or a chart measuring itself widens its column.
- Charts use `src/lib/components/BarChart.svelte`: Burrow sticker bars from one baseline, an optional dashed target and trend line, one tab stop with arrow keys and a live region, a tooltip on hover or tap, and click (not tap) to open what a bar stands for. Small multiples share `bind:active` inside an element marked `data-chart-group`.
- Motion: a new screen gets its entrance for free if its cards sit in a `TrailPath` (they rise in one after another); mark other lists `mk-stagger`, show totals with warren/web's `Count` so they count up, and import transitions (`fly`, `rise`, `row` for list rows, `flip`) from `warren/web` rather than `svelte/transition`, so reduced motion stays still. New CSS motion goes inside the `no-preference` block at the end of `layout.css`; an entrance added there also goes in its `mk-returned` list, so it doesn't replay on a screen gone back to. The nav's current pill is one sliding blob (warren/web's `slidingPill`, styled as `wn-pill-blob`), and the nav is the same element on every screen, so on day screens Bao ducks behind it (`mk-peek--away`) instead of the nav being swapped.
- Feeling like an app: screens change with `pageTransition` (`+layout.svelte`; `TABS` in `src/lib/nav.ts` are the nav's own screens, which cross-fade; anything else slides in from the right and back out), and the bottom nav, the side rail and Bao's message button hold still meanwhile (`data-wn-keep="dock"`, `"rail"`, `"fab"`). A new top-level screen goes in both `NAV_ITEMS` and `TABS`. Every sheet goes through `Sheet.svelte`, which has the grab handle and pulls down to close (`dragToDismiss`; its title is a handle too on phones); `<main>` follows a swipe in from the left edge back to the previous screen (`swipeBack`) when there is one below a top-level screen. Give tappable buttons, rows and cards `wn-press`, call `haptic()` (`success` on a save or log, `warning` on a delete, `select` on an undo), and show a first load as `mk-skeleton wn-skeleton` shapes rather than a spinner.
- Reminders: `src/lib/push.ts` subscribes this device (permission is asked from a tap) and re-registers it whenever Settings opens; signing out turns it off. The service worker shows each push as a notification tagged `reminder` and, on a tap, posts `{type: 'open', url}` to an open window (the layout navigates) or opens one. `static/icons/badge-96.png` is the white-on-transparent status bar icon Android wants.
- Fredoka and Figtree are bundled from `@fontsource` (Latin only) so the PWA works offline.
